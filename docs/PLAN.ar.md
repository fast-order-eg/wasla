# الخطة الكاملة المعدّلة — وصلة

**تاريخ الخطة: 1 نوفمبر 2026.** الخطة تجمع الهدف النهائي والنسخة الأولى، وتفصل المنفّذ عن الربط غير المتاح بعد. راجع TASKS.ar.md لحالة كل مهمة بدل افتراض أن كل ما في هذه الوثيقة تم إنجازه.

## 1. الهدف التجاري

نوفر وقت تجهيز المحتوى والردود ومتابعة البيع، ونقلل أخطاء الأوردرات. نجاح المشروع يُقاس بالربح من طلبات مُسلّمة والوقت المتوفر، وليس بعدد الحسابات أو المنشورات.

البداية منتج إلى ثلاثة وقنوات قليلة. الماركت بليس والجروبات يفضلوا ضمن التسويق العضوي، ولا يشترط شراء إعلانات. نتوسع لما القياس يثبت فائدة حقيقية.

## 2. القرارات المتفق عليها

- شبكة الموبايل خيار أساسي لاتصال المتصفحات عند مناسبة التغطية والتكلفة؛ اتصال الوكيل بالسيرفر يستخدم اتصال الكمبيوتر المستقر.
- لا تغيير إجباري للـIP ولا شرط عدم تكرار آخر 30 عنوانًا. تسجيل الشبكة للتشخيص فقط.
- بروكسي الموبايل يحتاج إعدادًا واختبارًا على الجهاز الفعلي. النسخة الحالية تختبر منفذ TCP فقط؛ ده لا يثبت مرور كل المتصفح عبر الموبايل أو توفر الإنترنت.
- AdsPower اختياري لإدارة جلسات مصرح بها؛ لا ضمان ضد الحظر ولا شرط لعمل لوحة التحكم.
- ردود الصفحات الرسمية مستقلة عن تشغيل المتصفحات المحلية عندما يُفعّل الربط الرسمي اللازم.
- الحسابات الشخصية وMarketplace مسار مساعدة بشرية أولًا. بحث ربطها الآلي تجربة منفصلة، وليس وعدًا في المنتج.
- إتمام الأوردر داخل الشات ممكن. عدم إرسال روابط اختيار لتسهيل رحلة العميل، وليس قاعدة لمنع الحظر.
- المساعد لا يمتلك سلطة تعديل السعر أو المخزون أو تأكيد البيع. البرنامج يتحقق والعميل يؤكد.

## 3. رحلة المستخدم

تضيف المنتج وسعره ومخزونه وصوره واختياراته وحقول العميل المطلوبة. تجهّز مسودة نشر وتراجعها وتنشرها بالطريقة المتاحة للقناة. عندما يرسل العميل، تدخل الرسالة رسميًا للقنوات المرتبطة أو تسجلها يدويًا بوضوح. المساعد يقترح ردًا من بيانات المنتج، وتراجعه.

تُجمع بيانات العميل ويُراجع المخزون والشحن. يعرض ملخص المنتج والاختيارات والكمية والإجمالي والعنوان. لا يتحول الطلب لمؤكد قبل موافقة صريحة مسجلة. بعدها تجهيز، شحن، تسليم أو إلغاء/مرتجع.

عند الشكوى أو تضارب البيانات أو فشل الخدمة، يتولى الموظف. استلام الموظف يوقف المساعد للمحادثة حتى استئناف واضح.

## 4. البنية التقنية

### السيرفر

Node.js ESM + Express، لوحة HTML/CSS/JavaScript، MySQL للإنتاج، HTTPS أمام الخدمة. قاعدة البيانات لا تُفتح للأجهزة المحلية. مفاتيح الخدمات على السيرفر فقط، ومفتاح الوكيل منفصل عن كلمة مرور المدير.

SQLite للتجربة المحلية فقط. التخزين الأولي JSON داخل جدول بمعاملات لتسهيل تجربة الفكرة؛ المرحلة التالية مخطط مطبع وفهارس حسب الاستخدام الفعلي.

### استقبال الرسائل

Webhook رسمي لصفحة مهيأة بالصلاحيات، يتحقق من التوقيع على الجسم الخام. يحفظ الحدث قبل إقرار الاستلام، ثم يعالجه بطابور دائم. لكل رسالة مفتاح منع تكرار. الفشل له عدد محاولات وحد أقصى، وبعدها يظهر للمراجعة. الرسائل غير النصية تُعلّم للمراجعة البشرية.

### المساعد

واجهة موحدة لمزود الذكاء الاصطناعي. الافتراضي قواعد محلية. المحوّل الأول Gemini API، وليس Vertex AI؛ إذا كان حساب المشروع سيستخدم Vertex نضيف موصلًا منفصلًا بهوية خدمية. اختيار الموديل إعداد يُراجع وقت النشر. المزود يفهم النص ويقترح ويستخرج فقط، والنتائج غير الموثوقة تراجع.

### الوكيل المحلي

برنامج مستقل يرسل نبضة اتصال ونتيجة فحص منفذ البروكسي بمهلات وإعادة محاولة محدودة. يتوقف عند خطأ صلاحيات أو إعداد سياسة مخالف. لا ADB ولا تغيير وضع طيران ولا نشر أو رسائل تلقائية في النسخة الحالية.

## 5. أجزاء المنتج

### الكتالوج

اسم ووصف وصور وسعر بالقروش واختيارات ومخزون وحالة بيع. حقول العميل المطلوبة قابلة للتخصيص. لاحقًا تفصل كل تركيبة لون/مقاس كـSKU بمخزون مستقل، مع سجل تسويات يمنع ضياع تحديثات متزامنة.

### الشحن

النسخة الأولى تكلفة معروفة يُدخلها الموظف قبل التأكيد. لاحقًا جدول محافظة/منطقة وشرائح وزن أو كمية حسب نشاطك. المنطقة غير المعرفة تتحول لمراجعة بشرية. لا يختلق المساعد سعر شحن.

### النشر

مسودة عنوان ووصف من المنتج، مكان النشر، حالة يدوية، ورابط النتيجة. لا تعادل «جاهز» أو «نشر مسجل» تنفيذًا خارجيًا. لاحقًا صور محسنة للعرض والوضوح وحملات مقاسة؛ لا هدف لتجاوز بصمة الصور.

### المحادثات

قناة ومصدر واضحان، سجل رسائل، منتج مختار، بيانات عميل، مسودة رد، وتسليم للموظف. عند وصول رسالة أثناء توليد اقتراح، يُرفض الناتج القديم. البيانات المستخرجة اقتراحات لا تعدّل بيانات العميل دون مراجعة.

### الأوردرات

انتظار تأكيد ← مؤكد ← تجهيز ← شحن ← تسليم. الإلغاء قبل الشحن يرجع المخزون المحجوز مرة واحدة. المرتجع في النسخة الأولى يعني مستلمًا وصالحًا لإعادة التخزين، وليس مجرد طلب إرجاع. سعر الطلب وشحنه محفوظان كلقطة وقت الاتفاق؛ تغير سعر المنتج قبل التأكيد يمنع تأكيد مسودة قديمة.

### الإدارة والتقارير

محادثات مفتوحة، طلبات تحتاج تأكيد، طلبات تنفيذ، إجمالي طلبات مسلّمة. الإيراد ليس الربح؛ المرحلة التجارية تضيف تكلفة البضاعة والشحن الذي تتحمله والمرتجعات والإعلانات والوقت والمصاريف لتحديد هامش المساهمة.

### التشغيل

سجلات تشغيل بدون نصوص العميل أو المفاتيح، نبضات ومهلات، نسخ احتياطي واسترجاع، مراقبة تنتهي بتنبيه ذي معنى. لوحة الحالة تميّز «غير مهيأ» و«مهيأ» و«تم التحقق باستقبال حدث»؛ ولا تدّعي أن الإرسال متاح بمجرد وصول Webhook.

## 6. مراحل التنفيذ

1. توثيق الاتفاق وتقسيم الملكية وعقد API.
2. تنفيذ متوازٍ: بيانات وأوردرات، لوحة عربية، وكيل محلي. بالتوازي يجهز المنسق المصادقة وموصلات الرسائل والمساعد.
3. دمج الأجزاء واختبار مسار كامل على بيانات تجريبية.
4. توثيق الإعداد وحدود النسخة وحفظ خطة المهام التالية.
5. تجربة MySQL على خادم معزول، إعداد HTTPS والنسخ الاحتياطية والصلاحيات.
6. ربط صفحة يختارها المالك بعد إتاحة الصلاحيات، واختبار استقبال رسالة حقيقية وعدم تكرارها.
7. اختيار AI ومدى مشاركة بيانات العملاء، وتجربة مسودات على عينة مراجعة.
8. إضافة إرسال رسمي بموافقة الموظف فقط بعد تهيئة بيانات الوصول، مع نافذة المراسلة وسجل إرسال ومنع تكرار. الإرسال الآلي لاحقًا لقواعد محدودة بعد قياس النتائج.
9. اختبار تشغيل محدود وقياس تكلفة الطلب المسلّم ووقت المراجعة والأخطاء.
10. تطوير الشحن والـSKU والتقارير ثم التوسع حسب القياسات.

## 7. معايير قبول مهمة

- عميلان لا يحجزان آخر قطعة مرتين.
- إعادة تأكيد نفس الطلب لا تخصم المخزون مرة ثانية.
- الإشعار المكرر لا ينشئ رسالة أو أوردرًا جديدًا.
- تغير السعر قبل التأكيد يمنع التأكيد الصامت.
- تدخل الموظف أو وصول رسالة جديدة يُبطل الاقتراح القديم.
- انقطاع الخدمة لا ينتهي بطلب «مؤكد» من غير موافقة.
- لا إرسال أو نشر خارجي في التجربة؛ كل حالات الواجهة صادقة.
- الوكيل لا يبدل الـIP ولا يمنع العمل بسبب عنوان متكرر.
- فشل الربط يظهر للمستخدم، وليس نجاحًا افتراضيًا.

## 8. البيانات المطلوبة للمرحلة المتصلة

تحديد صفحة النشاط ومالكها، ودومين وسيرفر صالحين، وحساب MySQL تجريبي، وصلاحيات Meta المطلوبة، ثم مفتاح AI وموديل مدعوم إذا رغبت. تُدخل الأسرار في البيئة محليًا أو على السيرفر؛ لا تُكتب في الوثائق أو الرسائل أو Git.

لا يلزم أي اشتراك AdsPower أو بروكسي أو حساب AI لتجربة النسخة المحلية.

## 9. تقييم الجدوى

فترة تجريبية مقترحة 2–4 أسابيع بعد جاهزية الربط، وتمتد إن كانت عينة المحادثات صغيرة. نسجل مصدر كل طلب ومبيعاته المسلّمة والوقت اليدوي. لا نعتبر مجرد مرور التجربة دون حظر ضمانًا للمستقبل.

نقطة التعادل = التكلفة الشهرية الكاملة / هامش المساهمة من الأوردر الإضافي المسلّم. التوسع قرار مبني على هذه النتيجة وجودة الخدمة، وليس زيادة عدد الحسابات تلقائيًا.
