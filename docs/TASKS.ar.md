# التاسكات التفصيلية وتوزيع التنفيذ

تاريخ: 1 نوفمبر 2026. الحالات تخص هذه النسخة، وليس هدف الإنتاج النهائي.

**توزيع الوكلاء:** backend للبيانات والأوردرات؛ dashboard للواجهة؛ worker للجهاز المحلي؛ المنسق للمصادقة والتكامل والاختبارات والوثائق. تم التنفيذ في مجلد مشترك مع ملكية ملفات محددة في CONTRACT.md. انتهت جولات الوكلاء الفرعية أثناء الدمج بسبب حد الاستخدام، وأكمل المنسق المراجعة والإصلاح والوثائق على الملفات المحفوظة.

## المجموعة A — الاتفاق والأساس | المنسق

- [x] A01: مراجعة المجلد وتعليمات المشروع. معيار القبول: عدم استبدال مشروع قائم أو تجاهل تعليماته؛ المجلد كان فارغًا.
- [x] A02: تثبيت قرارات الموبايل، عدم تدوير IP، فصل الرسمي عن الشخصي. المخرج: PLAN.ar.md.
- [x] A03: عقد البيانات والـAPI والملفات المشتركة. المخرج: CONTRACT.md؛ يعتمد عليه B/C/D.
- [x] A04: إعداد Node ESM وExpress وملف بيئة نموذجي وتجاهل الأسرار والبيانات. المخرج: package.json و.env.example.

## المجموعة B — البيانات والبيع | backend ثم المنسق

- [x] B01: تخزين SQLite دائم ومعاملات وrollback وطابور يعزل التحديثات المتزامنة. اختبار تحديث متزامن وفشل معاملة.
- [x] B02: محوّل MySQL مع معاملات وقفل مشترك. الكود مكتمل؛ اختبار الخادم الفعلي في G01.
- [x] B03: إضافة وتعديل المنتجات والتحقق من السعر الصحيح والمخزون والحقول والروابط.
- [x] B04: إضافة قنوات يدوية وMessenger غير مهيأ. لا يستطيع العميل تزوير connected أو تفعيل الإرسال.
- [x] B05: إنشاء وقراءة وتحديث المحادثات والرسائل اليدوية. المصدر اليدوي ظاهر.
- [x] B06: استقبال رسالة خارجية بمعرف منع تكرار داخل معاملة.
- [x] B07: اقتراح رد خارج معاملة DB ثم إعادة فحص revision وحالة الموظف قبل حفظه.
- [x] B08: إنشاء طلب من سعر المنتج، التحقق من بيانات العميل والكمية والشحن، ومنع طلب مفتوح مكرر.
- [x] B09: تأكيد صريح، إعادة فحص السعر والمخزون، خصم ذري. الاختبار: طلبان على آخر قطعة ينجح واحد فقط.
- [x] B10: انتقالات التجهيز والشحن والتسليم والإلغاء والمرتجع، واسترجاع مخزون مرة واحدة فقط.
- [x] B11: تجهيز مهام نشر من المنتج وتسجيل النتائج يدويًا.
- [x] B12: ملخص إيراد طلبات مسلمة وسجل تشغيل منقح بدون بيانات Webhook الخام.
- [ ] B13: مخطط MySQL مطبع وفهارس ومخطط ترحيل من app_records. مطلوب قبل التوسع؛ يعتمد على قياسات G01.
- [ ] B14: مخزون SKU منفصل لكل لون/مقاس وسجل تسويات ومعالجة تغيير مخزون من موظفين متزامنين.
- [ ] B15: جدول شحن حسب المناطق ومراجعة المناطق غير المعرفة. حاليًا إدخال يدوي صريح.
- [ ] B16: فصل طلب الإرجاع عن الاستلام والفحص والتالف والمبلغ المسترد. حاليًا مرتجع صالح للمخزون فقط.

## المجموعة C — الواجهة | dashboard ثم المنسق

- [x] C01: لوحة RTL بألوان ثابتة وتنقل مناسب للشاشات الصغيرة وحالات تحميل وفشل وفراغ.
- [x] C02: دخول وخروج وإظهار وضع التجربة وحدوده.
- [x] C03: نظرة عامة من بيانات فعلية، بلا أرقام مبيعات مصطنعة.
- [x] C04: إدارة المنتجات والبحث وتعديل السعر والمخزون والخامة/الماتريال وروابط الصور وفولدر ميديا التسويق والحقول المطلوبة بالعربي.
- [x] C05: محادثات يدوية، ربط منتج، إدخال رسالة، مسودة ونسخ وتدخل موظف.
- [x] C06: بيانات عميل ونموذج أوردر وملخص إجمالي ثم تسجيل موافقة صريحة.
- [x] C07: حالات الطلب وسجلها ومراجعة إلغاء/مرتجع.
- [x] C08: تجهيز منشور ومراجعة محتواه ونسخه وتسجيل نتيجته يدويًا مع تضمين الخامة والماتريال.
- [x] C09: القنوات وحالة الوكيل والربط، وعدم الادعاء بالإرسال أو المزامنة الشخصية.
- [ ] C10: إشعارات Push للموبايل واختيار التنبيهات؛ لا يوجد إرسال إشعارات خارجية الآن.
- [ ] C11: صور منتجات مرفوعة وتوليد مقاسات/بطاقات سعر لتحسين العرض؛ بدون تجاوز بصمات الصور.

## المجموعة D — الجهاز المحلي | worker ثم المنسق

- [x] D01: إعداد HTTPS للسيرفر، واستثناء localhost صريح للتجربة، ومفتاح مستقل >=32 حرفًا.
- [x] D02: فحص منفذ بروكسي الموبايل بمهلة مع تمييز غير مهيأ عن فشل الاتصال. فحص TCP فقط.
- [x] D03: إرسال heartbeat بحالة وأسماء قدرات فقط بدون أسرار البروكسي.
- [x] D04: backoff محدود، توقف عند خطأ صلاحيات، وعدم الاستمرار في حلقة فشل لا نهائية.
- [x] D05: رفض سياسة تفعّل تغيير IP أو نشرًا تلقائيًا أو رسائل شخصية. لا أوامر ADB.
- [x] D06: اختبار الشبكة والمهلات والإلغاء وتنقيح الأخطاء بالوحدات ومحاكاة HTTP.
- [ ] D07: اختبار جهاز الموبايل الحقيقي ومسار خروج المتصفح وIPv4/IPv6/DNS والتغطية والتكلفة. يحتاج الجهاز والإعداد الفعلي، لا تنفذه نبضة TCP وحدها.
- [ ] D08: تقييم الحاجة إلى AdsPower وربطه فقط لو أضاف قيمة؛ لا شراء ولا تسجيل حساب تم.

## المجموعة E — التكامل والحماية | المنسق

- [x] E01: جلسة HttpOnly وSameSite، تحقق origin وJSON، حد محاولات الدخول، ومنع كشف التجربة خارج loopback.
- [x] E02: فصل مفتاح الوكيل عن جلسة المدير ورفض مفاتيح قصيرة وإعداد إنتاج غير آمن.
- [x] E03: مساعد محلي بدون تكلفة أو اتصال خارجي، وتحويل الشكاوى والشك إلى مراجعة.
- [x] E04: موصل Gemini API قابل للإعداد مع timeout وJSON validation وfallback؛ لا إرسال AI في demo.
- [x] E05: Webhook تحقق HMAC على raw body، ورمز تحقق، وتقييد الصفحة المعينة.
- [x] E06: تخزين الحدث قبل ACK، منع تكرار، lease للمعالجة، retries محدودة وحالة فشل.
- [x] E07: حجب payload وبيانات العملاء ومعرفات المعالجة من سجل التشغيل.
- [x] E08: استقبال المرفقات كحالة تحتاج موظفًا بدل ادعاء فهم الصورة أو الصوت.
- [ ] E09: هوية Vertex AI خدمية إذا اختير Vertex بدل Gemini API؛ الاختيار الحالي موثق في README.
- [ ] E10: إرسال Messenger رسمي بموافقة الموظف، Page token، نافذة مراسلة، outbox، وحالة نتيجة غير مؤكدة. **غير منفذ ولا مفعّل الآن**؛ يعتمد على G02 وتجربة فعلية.
- [ ] E11: رد تلقائي محدود للقناة الرسمية بعد قياس الجودة، زر إيقاف عام، سقف تكلفة، ومراقبة أخطاء. يعتمد على E10 وG04.
- [ ] E12: صلاحيات فريق وجلسات مشتركة بين عمليات السيرفر وتدوير أسرار وسياسة احتفاظ وحذف بيانات العملاء قبل تشغيل فريق فعلي.

## المجموعة F — الدمج والتحقق | المنسق

- [x] F01: اختبارات domain وworker وintegration دون عملاء أو خدمات حقيقية.
- [x] F02: اختبار مصادقة وCSRF وrate limit، توقيع Webhook وإعادة الإشعار، وإيقاف AI في demo.
- [x] F03: دمج الواجهة مع الـAPI وتشغيل معاينة محلية.
- [ ] F04: إكمال اختبار رحلة المتصفح المرئي وتوثيق النتيجة؛ يُحدث هذا البند بعد انتهاء التحقق.
- [x] F05: إضافة واختبار تصدير أوردرات ونسخة احتياطية محلية واسترجاعها.
- [ ] F06: قياس أداء وأحمال واقعي وحجم ذاكرة وفهارس وطلبات API وإضافة pagination قبل حجم كبير.

## المجموعة G — بوابات التشغيل الحقيقي | يحتاج إعدادات يملكها المستخدم

- [ ] G01: MySQL معزول، صلاحيات محدودة، تشغيل اختبارات عليه وتجربة backup/restore. لا يوجد خادم أو بيانات وصول مقدمة.
- [ ] G02: اختيار الصفحة وربط تطبيق Meta والصلاحيات المطلوبة ودومين HTTPS. اختبار رسالة حقيقية قبل وصف القناة جاهزة.
- [ ] G03: إعداد AI بمفتاح وموديل مدعوم ومراجعة مشاركة بيانات العملاء والتكلفة.
- [ ] G04: مراجعة عينة مسودات وأسعار وشحن وطلبات وتدخل بشري؛ تسجيل نسبة الأخطاء، لا افتراض دقة 100%.
- [ ] G05: نشر على السيرفر المختار بعد مراجعة النسخة والإعدادات. لم يُنشر أي موقع أو خدمة خارجيًا.
- [ ] G06: تجربة تجارية 2–4 أسابيع بعد الربط: زمن الرد، التدخلات، الأخطاء، الطلبات المسلمة، وهامش المساهمة.
- [ ] G07: اتخاذ قرار التوسع أو التعديل حسب الربح والوقت المتوفر. أتمتة الحسابات الشخصية تبقى تجربة مستقلة غير مضمونة.

## ترتيب التنفيذ بعد النسخة المحلية

F04 وF05 أولًا؛ بعدها G01/G02/G03 بالتوازي عند توفر إعداداتها. B14/B15/C11 يمكن تطويرها دون Meta حسب بيانات المنتجات الحقيقية. E10 بعد G02 فقط، وE11 بعد قياسات G04. لا شراء باقات كبيرة أو الاعتماد على ربط الحساب الشخصي قبل نتيجة التجربة.
